------------------------------------------------------------------------
一、这个版本解决什么问题
------------------------------------------------------------------------

原来的 FGO W.apk 只能在 Android 12 上跑,在 Android 13 及以上会黑屏退出。
原因不是游戏本身,而是游戏启动时读一个系统属性:

    ro.secure

该属性的 SELinux 类型是 userdebug_or_eng_prop。这个类型只存在于
userdebug / eng 版系统上;正式版(user)系统里,AOSP 的规则
userdebug_or_eng() 展开为空,所以 app 域对它没有任何权限。

后果:内核不会把这块属性区映射进游戏进程。libc 的
SystemProperties::Find() 拿不到这个区,返回 NULL,游戏把"读不到
ro.secure"当成运行环境被篡改,直接 abort —— 表现就是黑屏闪退。

黑屏根因的确证过程(两种 SELinux 状态下的对照):
    Enforcing  :游戏进程只映射 164 个属性区(不含 userdebug_or_eng)
    Permissive :映射 591 个(含 userdebug_or_eng),游戏正常
另外实测在 Enforcing 下临时注入一条
    allow untrusted_app_29 userdebug_or_eng_prop file { open read map getattr }
游戏立刻完全正常 —— 这就是"root 方案"的依据(见 root方案/ 目录)。

------------------------------------------------------------------------
二、免 root 版的原理
------------------------------------------------------------------------

既然无法让内核映射这块属性区,就绕开"映射"这一步:在游戏进程内部,
把 libc 取属性区的那个间接调用替换掉。

libc 的实现(SystemProperties::Find):

    ldrb w8, [x0, #0x490]        ; contexts_initialized_ 必须为 1
    cbz  w8, fail
    ldr  x0, [x0, #0x480]        ; self->contexts_
    ldr  x8, [x0]                ; contexts_->vtable
    ldr  x8, [x8, #0x18]         ; vtable[3]
    blr  x8                      ; vtable[3](obj, name) -> prop_area*
    ... prop_area_find(area, name) ...

关键点:目标是**从内存里读出来的**(blr x8),不是写死的。于是把
self->contexts_ 的虚表第 3 项原地改掉,换成我们自己的函数:

    my_vt3(obj, name)
      ├─ 名字在我们的伪造表里 -> 返回我们自建的 mini prop_area
      └─ 否则              -> 转发给原来的 vtable[3]

返回的 mini prop_area 是按 libc 期望的格式手工构造的,一个区只装一个
属性(调用方拿到区之后只会用同一个名字去查,所以一个够用)。
布局与实际属性区完全一致,偏移都是区内的相对偏移,因此
prop_area_find() 能正常解析。区里的边界检查是
"它自己缓存的 bytes_used >= 我们的偏移",我们的偏移很小,必然通过。

这样,即使内核一个字节都没有映射这块属性区,游戏也能读到
ro.secure = "1" 以及全部 Android 11 伪装属性。

------------------------------------------------------------------------
三、为什么一定要用"改虚表"这一条路(重要)
------------------------------------------------------------------------

游戏有反篡改检测。实测结果:

  A. 改 libc 的**代码页**(把 __system_property_find 的跳转改掉,
     甚至只是原样写回同样的字节)          -> 立刻 abort
  B. mmap(MAP_FIXED) 把代码页换成匿名副本   -> 立刻 abort
  C. 只往 libc 的 .bss 写 1 个字节          -> 立刻 abort
  D. 原地改虚表项(数据页,GNU_RELRO)     -> **不触发检测,游戏正常**

错误码对照:
    反篡改触发           -> ErrorCode = 18593409
    只缺伪装属性         -> ErrorCode = 2
    一切正常             -> 进入标题画面

所以本方案只碰数据页,完全不改任何代码页 —— 这也是它能免 root 且
不被检测的原因。原版 spoof 库(改属性区的页 + 改代码页 hook)在
正式版系统上做不到这一点,这就是它在 Android 13+ 上黑屏的直接原因。

------------------------------------------------------------------------
四、兼容性
------------------------------------------------------------------------

* ABI:arm64-v8a(真机)。APK 内的 x86_64 库仍是原版,模拟器上
  不适用(原因同上:原版依赖改代码页和映射属性区)。
* 系统:Android 15 / 16 实测正常;Android 17 理论可行(机制一致,未实机验证)。
* 不需要 root,不需要 Magisk,不需要改 SELinux,不需要解锁。
* 不依赖任何外部配置文件:伪装表内置在库里,app 私有目录被清空后
  也能自动从 APK 重建。

健壮性设计:
* contexts_ 字段偏移(本机 0x480)是**运行时扫描** libc 指令流得出的,
  不是写死的,换系统版本也能自适应。
* 找不到时自动回退到内置默认值。
* 属性区模板在构造后逐条自检,不匹配会打 MISMATCH 日志。

------------------------------------------------------------------------
五、安装方法
------------------------------------------------------------------------

1. 卸载旧版(会有提示,注意:Android 11+ 下
   /sdcard/Android/data/com.aniplex.fgowaltz 里是游戏的 849MB 数据,
   卸载会一并删除。要保数据就**直接覆盖安装**,不要卸载)。

2. 覆盖安装(推荐,保数据):
       adb install -r FGO_W_noRoot.apk
   或直接把 APK 拷到手机点安装。签名与旧版一致,可以直接覆盖。

3. 启动游戏 -> 标题画面 -> 点一下 -> 会提示"サーバーとの通信に
   失敗しました"(游戏已停服,属正常)-> 点「閉じる」进入离线模式。

------------------------------------------------------------------------
六、排查用的调试开关(一般用不到)
------------------------------------------------------------------------

库会读 /data/local/tmp/fgowhook.cfg(存在才读)。可写:

    trace=1        打印每个被查询的属性名和调用来源
    areadump=1     打印返回的 area 十六进制
    area=0         关掉伪造(回到黑屏,用于对照)

例如:
    adb shell "echo trace=1 > /data/local/tmp/fgowhook.cfg"

日志标签:FGOwHook
    adb logcat -s FGOwHook:*
